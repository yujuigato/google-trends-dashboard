Background

這個系統在解決什麼問題？

業務與行銷團隊需要掌握市場脈動，但 Google Trends 原始介面難以做跨週比較，熱搜也混雜大量娛樂新聞干擾判斷。

😣 過去的痛點

  • Google Trends 介面無法快速比較不同週的趨勢變化
  • 熱搜清單混雜娛樂、新聞，商業訊號被稀釋
  • 無法自動判斷哪些關鍵字是「新出現」還是「持續上升」
  • 主題聚合需要人工整理，一週一次要花半天

✅ 系統如何解決

  • Selenium 每週自動爬取，商業白名單過濾所有非商業雜訊
  • 自動分類 4 種趨勢方向（新興 / 上升 / 持平 / 下降）
  • 10 大商業主題自動聚合，同主題關鍵字一目瞭然
  • 爬取 → 分析 → 發布全程自動，業務隨時查看最新資料

1

自動爬取

Windows Task Scheduler 每週觸發，Selenium 以 headless Chrome 模擬瀏覽器操作，爬取 Google Trends 台灣商業類別的週度熱搜排名。

2

商業白名單過濾

Google Trends 熱搜混雜娛樂明星、體育賽事等雜訊，白名單過濾只保留與商業環境相關的關鍵字。

3

趨勢方向分類

比對前幾週資料，自動判斷每個關鍵字的趨勢方向，讓使用者快速識別新興機會。

★ 新興（本週首次出現） ↑ 上升（排名提升） → 持平 ↓ 下降（熱度消退）
4

主題聚合與視覺化

Papermill 執行分析 Notebook，將語意相關的關鍵字歸入 10 大商業主題，Chart.js 生成互動式 HTML 儀表板。

5

自動發布

生成的 HTML 自動 git push 到 GitHub Pages，業務當天就能查看最新儀表板，不需要任何後端伺服器。

Engineering Challenges

解決了哪些技術難題？

Challenge 1

爬取動態渲染的 Google Trends

Google Trends 由 JavaScript 動態渲染，一般的 requests 爬蟲看到的是空白頁面。

↓ 解決方案

Selenium 控制 headless Chrome 實際執行 JS，等待元素出現後再擷取，模擬真實使用者瀏覽行為

Challenge 2

白名單的維護成本

商業議題範疇持續演變，白名單若需要工程師修改程式才能更新，維護成本太高。

↓ 解決方案

白名單存為獨立設定檔，業務人員可直接編輯；系統每次執行自動讀取最新版本，更新即時生效

Challenge 3

主題聚合的自動化

「AI 科技」、「半導體」等主題下的關鍵字每週不同，無法寫死規則；但完全靠 LLM 又太貴。

↓ 解決方案

主題定義（種子關鍵字 + 語意規則）固定，新出現的關鍵字依規則自動歸類；只有規則無法判斷時才呼叫 LLM

Challenge 4

零後端的即時發布

若需要後端伺服器，每次更新都要維護部署流程；但純靜態 HTML 的資料又是固定的，無法動態更新。

↓ 解決方案

每次分析完整重新生成 HTML（含資料），git push 到 GitHub Pages 自動發布；靜態但每週重新生成，達到「看起來即時更新」的效果

Competitive Intelligence Dashboard · 每日自動更新

Background

這個看板在解決什麼問題？

業務同仁很難逐一追蹤每家 ERP/CRM 競爭對手的負面消息（當機、資安漏洞、裁罰、倒閉等），逐一手動搜尋既耗時又容易漏掉。

😣 過去的痛點

  • 競爭對手數十家，逐一手動搜尋新聞不可行
  • 短公司名（如「正航」「凌越」）搜尋容易誤命中同名不同產業的無關新聞
  • 沒有系統化的方式判斷一則新聞是否真的構成「負面事件」

✅ 看板如何解決

  • 從業務日報萃取出的競爭者名單自動查詢 Google News
  • Gemini AI 逐則判斷「是否真的與該公司相關」與「是否為負面事件」，排除同名不同產業誤判
  • 依 ERP専屬／ERP同類（BPM/MES/SI）分類呈現，另設本公司自身新聞監控區塊

Engineering Challenges

解決了哪些技術難題？

Challenge 1

同名不同產業的誤判

短公司名容易命中無關新聞，例如「偉盟」誤命中「偉盟工業」炒股新聞，而非真正的競爭對手「偉盟系統」。

↓ 解決方案

Prompt 明確告知 Gemini 目標公司的產業背景（ERP/CRM 供應商），要求判斷「標題描述的公司是否真的在做企業管理軟體」，同名不同產業一律排除

Challenge 2

競爭者名單雜訊多

業務日報原始備註裡有大量空泛描述（如「其他既有ERP系統廠商」）與同賽道但非ERP的公司名稱，直接拿來查會浪費大量查詢額度。

↓ 解決方案

兩輪 LLM 批次分類清理：先排除空泛描述，再排除非ERP相關名稱，只保留真正的競品才納入監控

Regulatory Opportunity Dashboard · 每日自動更新

Background

這個看板在解決什麼問題？

法規上路往往逼企業導入或升級系統（例如強制電子發票、碳盤查申報），對 ERP 供應商是商機訊號，但法規多、變動快，業務難以即時掌握。

😣 過去的痛點

  • ESG、資安、碳費等法規領域眾多，業務無暇逐一追蹤
  • 只監控預先想到的法規清單，容易錯過剛冒出的新興法規（如某產業新規、修法）
  • 新聞看到了，也不容易快速判斷「誰會受影響」「什麼時候生效」

✅ 看板如何解決

  • 固定主題查詢＋廣泛偵測查詢雙軌並行，自動發現清單外的新興法規
  • Gemini 萃取「法規名稱／生效時間／適用對象」，快速掌握商機輪廓
  • 七大分類（ESG、資安、碳排、勞動、食安、稅務、採購）自動歸類呈現

Engineering Challenges

解決了哪些技術難題？

Challenge

「封閉清單」看不到新興法規

只監控預先設定的固定關鍵字清單，永遠只能看到已知的法規領域，看不到剛冒出來、沒預先想到的新規。

↓ 解決方案

另外設計「廣泛偵測查詢」：用「強制實施」「新制上路」「主管機關公告」等不綁定特定法規名稱的通用語句查詢，讓 LLM 自己從新聞裡辨識出「這是什麼法規」，依萃取出的法規名稱分組，自動判斷是否為清單外的新主題並併入看板，讓系統具備真正的「發現」能力而非只有「確認」能力
